## Dedicated retention route and operational migration

It rejects query parameters, caller-selected dates and unauthenticated access. Both coverage ingestion and this independently authenticated cron bypass member session refresh. There is no production URL fallback.

Metrics preservation is exercised by isolated fixtures and the released SQL suite; the runtime postconditions are count/expiry checks, not a cryptographic audit of every metric or cell. ## Independent monitoring adapter and ingestion health

Proposed Healthchecks.io retention check uses cron schedule 0 8 * * *, timezone UTC, one-hour grace, and expects successful completion by 09:00 UTC. Empty POST /start, base success and /fail signals only; start must not count as success. Set any maximum-runtime grace so an 08:45 recovery cannot push the missed-run deadline past 09:00; verify this behavior in the selected provider before installation. The adapter pins HTTPS hc-ping.com with canonical UUID path, rejects credentials/query/fragment/redirects, omits credentials/referrer, sends no body data, and has 1.5s timeout. The UUID URL is itself a secret. Never print it. No check/account/key/destination is created here.

A failed start signal does not prevent deletion. A success heartbeat failure returns completed_monitor_failed/502 without undoing committed maintenance; a recovery invocation rechecks/skips DB work and retries empty signals. DB failure sends fail best effort. External missing-run detection catches complete absence of code execution. Owner must verify real provider semantics/delivery and a staffed info@varsityvue.com mailbox, including missed-run, explicit failure, failed notification delivery and recovery. No real email or heartbeat was sent during preparation.

Prepared ingestion monitoring keeps only capped accepted/database_failure/capacity_failure totals in one five-minute window per server instance. It inspects only a bounded database SQLSTATE, never diagnostic text in a signal. Five failures occupying at least half observed categories trigger fail; three successes in a new zero-failure window signal recovery. Pending signal retries are throttled to once a minute and coalesced while in flight. Inactivity never alerts; absence of opt-in is not a failure. Next after runs this optional work after the ingestion response so discovery/navigation do not wait. No request-correlated trail, exception log, identity, query, geography, payload, IP or persistent event history is recorded.

The per-instance adapter is useful but insufficient for fleet-wide detection: cold starts/reset/distribution may hide failures, and no new events means no automatic recovery proof. Native HTTP 503 alone cannot distinguish disabled/configuration from DB/capacity failure; verify a suitable bounded aggregate signal/export control or obtain separate authorization for a narrowly scoped solution.
